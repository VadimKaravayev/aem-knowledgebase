- [cloud-manager-ssl-certificates.md](cloud-service/cloud-manager-ssl-certificates.md) — Cloud Manager TLS for custom domains: **Adobe-managed DV** (Let's Encrypt, auto-renew every 3 months, prod *and sandbox*, **CNAME must stay or renewal fails and the site goes down**, 5 issuances/hostname-set/7 days) vs **customer-managed OV/EV** (you upload; DV and self-signed rejected; RSA **2048 only**, EC P-256/P-384, **ECDSA recommended**; key in PKCS#8, PEM files; one cert may serve several envs; wildcards ok). Limits: **70 certs/program incl. expired, 100 SANs/cert**. Platform TLS picks "most specific + most recently deployed" so overlapping wildcard + specific certs misbehave; cert must exist before a domain can be added. OpenSSL PFX/P7B/DER→PEM and local `openssl verify` recipes. UI flow: domain → cert → CDN config; **Business Owner/Deployment Manager only**; three paste fields (cert, PKCS#8 key, chain) and **leaf cert in the chain field = upload fails**; DV verifies domain *before* cert, OV/EV *after*. Lifecycle: green ≥14 d / orange <14 d (UI notifications only) / red expired; View and Update applies immediately; **delete needs a pipeline run to undeploy** and a DV cert with active domains cannot be deleted.
- [cloud-manager-custom-domain-names.md](cloud-service/cloud-manager-custom-domain-names.md) — Cloud Manager **Domain Settings** (Services menu; Business Owner/Deployment Manager; Sites programs, publish+preview, not sandbox). - [cloud-manager-newrelic-users-api.md](cloud-service/cloud-manager-newrelic-users-api.md) — AMS programs ship a **New Relic APM sub-account whose user access is managed via the Cloud Manager API**, not in New Relic. - [cloud-manager-variables.md](cloud-service/cloud-manager-variables.md) — Three Cloud Manager variable mechanisms, routinely conflated: **build env vars CM sets** (`CM_BUILD` — the "am I in CM?" switch, `CM_PROGRAM_ID/NAME`, `CM_PIPELINE_ID/NAME`, `CM_AEM_PRODUCT_VERSION`, `ARTIFACTS_VERSION`) with the two Maven activation idioms (`env.CM_BUILD` = only inside CM, `!env.CM_BUILD` = only local — the `!` form is the classic copy-paste trap; `env.` prefix required, `STAGE.CM_BUILD` never activates); **custom pipeline variables** you set via `aio cloudmanager:set-pipeline-variables` (`--variable`/`--secret`, masked in logs, build-only — e.g. private Maven repo credentials); **runtime environment variables** per environment (UI or `set-environment-variables`), consumed as `$[env:VAR]` / `$[secret:VAR]` in OSGi, uppercase/underscore names, no `INTERNAL_`/`ADOBE_` prefix, no pipeline run needed. Rule: `CM_*` = build facts given, pipeline vars = build values you give, env vars = runtime values; run modes pick the config file, variables fill its values.

- [content-distribution-journal.md](cloud-service/content-distribution-journal.md) — **AEMaaCS publication is not replication**: Sling Content Distribution in **journal mode** (`org.apache.sling.distribution.journal`) — an ordered append-only log as an Adobe pipeline service *outside* AEM, with each publish pod an independent subscriber holding its own offset (so autoscaled/redeployed pods just replay to catch up; author never knows how many publishers exist). Five Kafka topics (`aemdistribution_package|status|discovery|command|event`); **`package` and `status` support 1 partition only** → strict ordering → **head-of-line blocking**, the mechanism behind every "blocked queue". Two levels of indirection people conflate: asset **binaries** never travel in the package (FileVault **binary-less mode** → references into the **shared Oak blob store**, same trick as [shared-datastore-binaryless-replication.md](infrastructure-ops/shared-datastore-binaryless-replication.md) but built-in rather than configured), while the **package itself** rides *inside* the journal message (~<10 KB typical, 800 KB max) and only an oversized one is parked at `/var/sling/distribution/journal/packages` (12 h cleanup below min offset). Offsets are managed by agent code, **not** the log — stored under `/var/sling/distribution/journal/stores` in the **same atomic commit as the imported content** → exactly-once across pod replacement. **Diagnostic rule: the blocked queue renders on Author but the fault is on Publish** — items *are* queued, which proves export worked; an author-side fault fails at export and leaves the queue **empty**. The journal error queue **cannot retry** an item (unlike classic SCD) — remove it via Tools → Deployment → **Distribution UI**, then fix the content and republish. Service-user trap: publish imports as **`sling-distribution-importer`** (mapping `org.apache.sling.distribution.journal:importer`, defaults on `/content`,`/conf`,`/etc`, extend via repoinit per [repoinit-acls-on-apps-and-libs.md](cloud-service/repoinit-acls-on-apps-and-libs.md)) while author-side logs show `userId=replication-service`; and since the importer's is the only session on Publish, `jcr:createdBy`/`jcr:lastModifiedBy` there read as the service user — the original author is unrecoverable across that boundary, never build on it. **Exam vs. reality:** the cert answer for "pipeline timeout + blocked queues" is *importer lacks permissions on the Publish service* (distractors name the right symptom location, wrong tier) — but in production Adobe's own KBs say `AccessDeniedException` here *"possibly [has] no relation with the ACL / permissions"* (documented cause: `jcr:lockIsDeep` without `jcr:lockOwner`), `NamespaceException: Unknown namespace prefix` blocks queues too, and **content packages block it by themselves** (accesscontroltool #566, acs-aem-commons `ui.content` fix `58f4f4f`) — so check the blocking node before the ACLs. AEMaaCS only; 6.5/AMS still uses replication agents. Apache distribution-journal docs + Adobe KB ka-21668/ka-23465, Sept 2026.

- [rolling-deployment-two-version-overlap.md](cloud-service/rolling-deployment-two-version-overlap.md) — An AEMaaCS deploy is rolling: **old and new code serve traffic simultaneously**, and mutable content lands only after switchover, so "my new code and my new repo state arrive together" is never true. Mutable install order is **pre-startup** (index definitions) → **during startup** (service users, ACLs, node types — where repoinit runs, on a repo with no package content yet, see repoinit-acls-on-apps-and-libs.md) → **post-switchover** (everything else via Vault). Three consequences: (1) **spread service-user/ACL changes over two releases** (add the grant in N, switch code and remove the old one in N+1) or old nodes hit `LoginException`/`AccessDeniedException` mid-deploy; (2) **a rollback restores code but NOT content** — mutable structures from the failed release survive, so old readers must tolerate them or you fix forward; (3) **indexes set deploy duration** (reindex happens before the traffic shift, and both old and new index definitions must be serviceable during the overlap; ACS Commons Ensure Oak Index doesn't work on AEMaaCS). Reference facts: run modes are a **closed set** (`author`/`publish` × `rde`/`dev`/`stage`/`prod`, no custom ones, no per-environment package scoping); Cloud Manager packages are frozen with a **`cp2fm`** suffix (no rebuild/reinstall/download); manual one-off installs are **mutable-only and time out at 10 minutes** — the **"undefined" error is the request limit, not a failure: install continues in background, never retry** (the retry is what conflicts); **no FileVault install hooks in immutable packages** (mutable post-switchover packages DO support them); a **mixed** package installs only its mutable half silently at runtime (build log does warn `is of MIXED type`); **`getRunModes()` loses the environment type at runtime** — env dimension exists only for OSGi config resolution, branch via a config property; third-party packages via remote Maven repo or committed filesystem Maven repo, must pass cloud validation; OSGi *and* maintenance-task config must live in source control (Tools → Operations is gone). From the Adobe deploying-overview page, not reproduced against a live pipeline. **Also the KB home for Adobe's *Deploying / Overview* page** (re-read Oct 2026): code vs AEM-version releases are separate events; startup code may depend only on service users/ACLs/node types/indexes; repoinit's six reasons (startup-time, additive, atomic, locally validated, idempotent, independent of packages) + `RepositoryInitializer~<name>` config and `create path` before ACLs; file-based Maven repo POM snippet for third-party packages; the seven-step rolling sequence with mutable content last and canary deployments as the alternative; the **full closed list of 15 `config.*` folders**; Adobe's nine-item restriction summary.

- [multi-author-scaling.md](infrastructure-ops/multi-author-scaling.md) — Author-tier capacity drivers are parallel-author count + action types (not traffic/dispatcher-cache = publish concerns, not fail-safeness = HA concern). Whether there's a load balancer between authors depends on the NodeStore: TarMK doesn't support multi-node clustering, so "multi-author" means partitioning by tenant/team (no LB, direct routing); MongoMK lets multiple authors share one repo (LB makes sense, active-active). - [revision-cleanup.md](infrastructure-ops/revision-cleanup.md) — TarMK Online Revision Cleanup (default since 6.3), written for the results that look like failures. Three phases: estimation (**skips the whole run if the repo grew < 1 GB** since last compaction), compaction (full on Sundays, tail on weekdays, split by `full.gc.days` on `RevisionCleanupTask`; listing every day kills tail entirely), cleanup — and **disk is reclaimed only in the cleanup phase**, so a finished compaction with no size change is normal. Non-bugs: the **first ORC run reclaims nothing** (needs two generations), switching offline→online **doubles the repo** before settling back, and full compaction grows the repo before cleanup shrinks it (tail/full alternation sawtooths and delays reclamation). Hard aborts: free disk < **25%** of footprint (**not configurable**) and free heap < **15%** (`SegmentNodeStoreService#MEMORY_THRESHOLD`); size disks 2–3× the repo. Only revisions ≥ 24h old are eligible, and `SegmentNotFoundException` usually means app code held a reference past that 24h retention (a code bug, not a cleanup bug). Under write load ORC enters **forceCompact**, a write lock with a 1-minute timeout that yields to concurrent commits; healthy runs finish inside 2h. Monitor the `SegmentRevisionGarbageCollection` MBean (`EstimatedRevisionGCCompletion`, `startRevisionGC()`) and `TarMK GC #n:` log lines; the health check goes red only after **three consecutive cancellations** and **resets on restart**, so a routine restart erases the signal. Maintenance tasks run sequentially with no configurable order — give ORC its own window. Offline/oak-run is migration-only; oak-run must version-match Oak, `--force` is a one-way format upgrade, and `-Dsun.arch.data.model=32`/`-Dtar.PersistCompactionMap` are legacy. Windows never uses memory-mapped access — raise `segmentCache.size`. **Log → action matrix** (`estimation skipped because compaction is paused` = ORC disabled; `compaction failed … after 5 cycles` = write traffic in the window; `cleanup interrupted` = restart mid-window; `no base state available, running full compaction instead` = normal first/post-offline run) and the red-status decision list (move window / enlarge window / add heap / offline after a week without success). Oak Segment Tar migration: mandatory from 6.3, downtime, no reindex, `Invalid segment format` = wrong Oak not corruption, **offline-clean first** to shrink migration time. Sourced from the 6.4 doc, not reproduced locally.

- [tarmk-cold-standby.md](infrastructure-ops/tarmk-cold-standby.md) — Warm-spare HA for the **Author** tier on TarMK (6.5/AMS only; AEMaaCS has no equivalent). Primary opens TCP 8023, standbys poll every `interval` (5s) for the head segment id and pull unknown segments; checksummed, auto-retrying, sync-only (a standby serves no user requests, only the OSGi console), and failover is **manual** (stop standby, pull primary from LB, restart standby with `-r primary,crx3,crx3tar`, build a new standby). Configured from `install.primary`/`install.standby` folders: `StandbyStoreService` (`mode`, `port`, `primary.host`, `secure` must match both sides, `interval`, `standby.autoclean`, `standby.readtimeout=60000`, `primary.allowed-client-ip-ranges`) + `SegmentNodeStoreService` (`standby=true`, `service.ranking=100` on the standby). Trap 1: leaving `org.apache.sling.installer.configuration.persist` true makes the standby sync the primary's own config down and stop being a standby. Trap 2: PIDs moved in 6.3, `oak.plugins.segment.*` → `oak.segment.*`, so older configs are silently ignored. Biggest gotcha: **no integrity checking**, corruption replicates faithfully — this is availability, not backup; explicitly not for Publish (publish farm instead) and not a capacity play (see multi-author-scaling.md). Monitor `SecondsSinceLastSuccess` on the `type="Standby"` JMX bean, not `Running`. With Online Revision Cleanup the primary runs all three phases and the **standby automatically runs the cleanup phase only** (estimation/compaction never run there, so compacting a standby by hand does nothing) — verify by comparing segmentstore sizes. Offline maintenance order: stop sync → compact primary → resume → `cleanup()` on standby; datastore GC primary first, then `startBlobGC()` on the standby (no RepositoryManagement bean there); hotfixes are re-cloned from the primary, never applied in place. Cost is negligible on the primary, single-threaded and CPU-heavy on the standby. **Initial sync has no "done" message**: set `org.apache.jackrabbit.oak.segment` to DEBUG into its own `tarmk-coldstandby.log` on both sides and watch for the polling entries to stop (non-shared FileDataStore binaries log separately); verify the real role at `/system/console/status-slingsettings`; clear `crx-quickstart/install` before cloning so stale configs don't survive. - [dispatcher-caching-and-invalidation.md](dispatcher-url-delivery/dispatcher-caching-and-invalidation.md) — Dispatcher caching + invalidation + `dispatcher.any` condensed from Adobe docs. **Never cached**: `?` in URI, no extension, `Authorization` header (unless `/allowAuthorized "1"`), non-GET/HEAD, non-200, `no-cache`/`no-store`/`must-revalidate`. Two invalidation paths: **explicit flush** deletes the handle + all `handle.*` siblings then touches `.stat`; **auto-invalidation** (`/invalidate` globs, usually `*.html` only) re-fetches when file mtime < nearest `.stat`. `/statfileslevel N` scopes `.stat` touches to the activated subtree + ancestors (level 0 = whole site); `/statfile` ignored when set; `/gracePeriod` throttles bulk-activation storms; `/enableTTL` (4.1.11+, coexists with `.stat` from 4.3.5), `/serveStaleOnError`. **Flush agent belongs on Publish, not Author** (Author flush races replication → visitor re-caches the old page). Manual flush: `POST /dispatcher/invalidate.cache` with `CQ-Action: Activate|Deactivate|Delete|Test`, `CQ-Handle`, `Content-Length: 0`; body of paths + `Content-Type: text/plain` = delete **and** re-fetch; lock with `/allowedClients`. Load balancing: per-`/statistics` category response scores (max 8), `/unavailablePenalty`, `/stickyConnectionsFor` via `renderid` cookie (sticky paths must be uncacheable), `/failover "1"` + `/health_check`. Evaluation: farms bottom-up, virtualhosts top-down, `/filter` `/rules` `/invalidate` `/allowedClients` **last match wins**; `/clientheaders` is an allowlist; `/vanity_urls` bypasses `/filter`; Author Dispatcher must `deny *` in `/rules`; restart httpd after `/cache` edits. Review checklist of the classic stale-cache symptoms.
- [dispatcher-common-log-entries.md](dispatcher-url-delivery/dispatcher-common-log-entries.md) — Lookup table of the Dispatcher log lines you actually meet (Adobe AMS tutorial, 6.5; same lines on AEMaaCS via `aemdispatcher` log download): **glob warning** (≥ 4.2.x, rewrite with `/url`/`/extension`), **`Filter rejects`** (only at Info/Debug; admin-console rejects are intended; targeted allow rule for blocked fonts), **`Unable to connect socket … timed out`** = TCP never opened (render IP/firewall/AEM down) vs **`502 … 54034ms`** = AEM too slow (raise `/timeout` or fix AEM — thread dump, not timeout), **`Current cache hit ratio`** (target ≥ 80 %, low = flush frequency), **`Unable to create parent directory`** = fetch-vs-flush race or **SELinux `httpd_sys_content_t`**, **vanity URLs 404** = feature pack missing / anonymous denied, **`No farm matches host … selected last farm`** = silent fallback to the last loaded farm, `+ 24034ms publishfarm/0` = rendered-then-cached baseline. Includes the grep/awk one-liner that ranks blocked paths.
- [dispatcher-fundamentals.md](dispatcher-url-delivery/dispatcher-fundamentals.md) — Dispatcher as a **web-server module** (versioned independently of AEM) + the `dispatcher.any` sections the caching note skips. Request flow: cacheable? → cached file under `/docroot` (must equal the web server document root, **one docroot per farm**) → mtime vs `.stat`; **without auto-invalidation/TTL a cached file is served until physically deleted**. Two file-cache gotchas: **body-only cache** — without `/cache/headers` (4.1.11+, no globs; default set incl. Content-Type/Cache-Control; ETag needs Apache `FileETag none`) cached hits carry web-server-guessed headers (MISS correct, HIT wrong Content-Type); and OS filename limits → many-selector URLs silently never cache. Syntax: `$include` with wildcards, `${ENV_VAR}` interpolation. `/virtualhosts`: farms bottom-up, list top-down, full scheme+host+uri match > host-only > catch-all `*` in the **topmost** farm. `/renders`: **`/timeout` default `"0"` = wait forever — always set**, `/receiveTimeout` 600000, `/secure`, `/always-resolve`. `/filter` anatomy: deny-all baseline, last match wins, element rules (`/method /url /query /protocol /path /selectors /extension /suffix`, 4.2.0+) over **deprecated `/glob`** (matches the whole request line = the bypassable form); `"…"` = glob, `'…'` = **regex**; **purge cache after filter changes**; 404-test `/admin /crx /system/console …`. Also `/invalidateHandler` (script per flush: handle/action/scope), `/mode` 0755 ∩ umask, `/serveStaleOnError`. LB internals: ≤ 8 `/statistics` categories (first 8 only), selection = `renderid` cookie → lowest category score → first render; `/unavailablePenalty` (0.1 s units); retries = `/numberOfRetries` 5 × all renders, `/retryDelay` 1 s; `/failover`: 503 → next render, other 50x → `/health_check` arbitrates; `/stickyConnections` `/paths` + `httpOnly`/`secure` cookie flags, sticky paths must be uncacheable. Author Dispatcher: **never cache with Touch UI**, delete cached `/libs`+`/apps` after patches. Debug: loglevel 3→0, **Trace 4 names the blocking filter rule**, `/info "1"` + `X-Dispatcher-Info` header → `X-Cache-Info` verdict. Docs-based Oct 2026.
- [dispatcher-ignoreurlparams.md](dispatcher-url-delivery/dispatcher-ignoreurlparams.md) — Dispatcher `/ignoreUrlParams`: controls which query-string params are cache-relevant (distinct from `/filter`, which is request security, and `/rules`, which is path cacheability). Config shape is a glob allow/deny list like `/filter`, last-match-wins, `/type "1"` = ignore param for cache-key purposes. Two patterns: allowlist-the-ignorable (deny-all baseline + `1` for known tracking params) vs wildcard-ignore-all-deny-the-dynamic (`1` baseline + `0` for the few content-affecting params like search) — the latter is the exam-favored fix when campaign/tracking params vastly outnumber functional ones. Exam trap: offering a `/filter` change as the caching fix — `/filter` is security, not cache optimization.
- [dispatcher-permission-sensitive-caching.md](dispatcher-url-delivery/dispatcher-permission-sensitive-caching.md) — **`/allowAuthorized` is not "cache on/off" — it asks "may the security check be skipped?"** (`1` = treat protected pages as public, serve cached copies to *anyone*; `0` = never skip). Three farm postures: `0` alone = authenticated requests bypass cache entirely (safe, slow — the only case where "0 = don't cache" is true); `1` = blind caching (safe only when all logged-in users see identical content); **permission-sensitive caching** = `/sessionmanagement` (farm-level secure sessions) or `/auth_checker` (per-page HEAD to an AEM authorizer servlet, the AEMaaCS-documented pattern) = *cache once, check each visitor at the door* — and both **require `/allowAuthorized "0"`**; Adobe documents `/sessionmanagement` + `"1"` as **mutually exclusive**. Exam trap (CUG pages not cached despite `/sessionmanagement` added): leftover `"1"` blocks the session gate — the misread is "1 caches *more* so can't be the blocker"; with session management present the gate dominates and unvalidated requests are proxied uncached. Distractor taxonomy: `/rules` = which paths, `/clientheaders` = forwarding (additive answer covered by existing `"*"` changes nothing), `/stickyConnectionsFor` = LB pin taking a *content* path. **Real-world gotcha the exam skips:** CUG login yields a `login-token` **cookie**, so `/header "HTTP:authorization"` never establishes a session — production needs `/header "Cookie:login-token"` too, not just the flag flip. Docs-based, interaction not lab-verified.
- [sling-dynamic-include.md](dispatcher-url-delivery/sling-dynamic-include.md) — Sling Dynamic Include (SDI): keep a page cacheable at dispatcher/CDN while dynamic components (stock price, FX, personalized fragments) stay fresh, no component changes. Servlet filter swaps matched resource types for include placeholders + `nocache` selector dance; SSI (Apache `mod_include`) / ESI (Varnish/CDN) / JavaScript (AJAX) include types; OSGi config options (base path regex, resource types, TTL, selector); limitations (no POST/query-string/suffix components, disable debug comment for non-HTML); when to use vs AJAX lazy-load vs Sling Jobs. Note: "Sling Async Include" is not a real feature name.
- [cors-policy-and-dispatcher.md](dispatcher-url-delivery/cors-policy-and-dispatcher.md) — Browser cross-origin access to AEM lives in **three places that must agree**: the Granite policy factory `com.adobe.granite.cors.impl.CORSPolicyImpl` (full property table: `alloworigin`, `alloworiginregexp`, `allowedpaths`, `supportedheaders`/`methods`, `exposedheaders`, `maxage`, `supportscredentials`), the dispatcher's `/clientheaders` (pass `Origin` + `Access-Control-Request-*` **in**, or the handler never sees an Origin to match), and the dispatcher's `/cache/headers` (cache the `Access-Control-*` **out**, 4.1.1+). **Matching is first-match-wins on Origin × path, and default is deny** (no match denies; *zero* policies denies) — so a broad early policy **shadows** a narrower later one and the symptom is "my new CORS config does nothing," an ordering bug dressed as a broken config. Adobe prefers one policy per origin hostname over broad regexes. **`allowedpaths` are regexes and Adobe's own examples leave `.` unescaped** (`endpoint.json`) — nothing validates them and an over-broad pattern fails **open**. **Authenticated recipe's missed step:** beyond `supportscredentials:true` + `Authorization`/`CSRF-Token` headers, you must add **`/libs/granite/csrf/token.json` to `allowedpaths`** — the client fetches the token cross-origin first, so omitting it fails at the token fetch and points at anything but CORS. **Diagnostic signature: HTTP 200 with no `Access-Control-Allow-Origin` = a CORS denial, not a routing failure** → logger `com.adobe.granite.cors` DEBUG (denial reasons) / TRACE (all requests); replay with curl *including* `Origin`; check auth/CSRF/dispatcher filters aren't rejecting before CORS is consulted. Cacheable on anonymous publish only; flush + restart web server after any change. Includes flagged inference on why multi-origin publish moves up to the dispatcher (one cached response carries one `Access-Control-Allow-Origin`). Ships in `ui.config`, so the replace-not-merge runmode rule applies. `*` origin is honoured only for credential-less requests (with `supportscredentials:true` the browser rejects it — spec, not AEM); every Publish CORS change needs a cache invalidation, Adobe suggests purging on each deploy; the page's JSON has comma typos. 6.4/6.5 page, re-read Oct 2026.
- [ssl-termination-sling-mapping-404.md](dispatcher-url-delivery/ssl-termination-sling-mapping-404.md) — LB terminates SSL + forwards plain HTTP with X-Forwarded-Proto to AEM → all requests 404 unless BOTH fixed: Felix HTTP Service SSL Filter configured to trust the forwarded header (not Granite SSL Connector Factory — that's only for AEM terminating SSL itself), AND Sling Mapping exists at /etc/map/https/host.443 (not just /etc/map/http/host.80). Fixing only the mapping does nothing if AEM never learns the request was HTTPS.
- [sling-resource-resolution-mapping.md](dispatcher-url-delivery/sling-resource-resolution-mapping.md) — `/etc/map`, `sling:alias` and vanity paths as **two opposite operations sharing one config tree**: `resolve()` (URL→resource) and `map()` (resource→URL, i.e. every link AEM renders). **The reverse-mapping trap:** wildcard/regex entries in root-level mappings are silently unusable for `map()` — Sling can't run a pattern backwards — so requests work, links come out as raw internal paths, and people debug the templates. Inbound matching is against a **constructed virtual path `{scheme}/{host}.{port}/{uri_path}`**, which is the entire reason nodes are named `www.example.com.443` and why an instance that thinks it serves HTTP never reads the `https` subtree ([ssl-termination-sling-mapping-404.md](dispatcher-url-delivery/ssl-termination-sling-mapping-404.md)). Longest match, regexes in order, first wins (same shadowing failure as CORS policies); `sling:internalRedirect` is multi-value tried in sequence; `sling:status` default 302. **`sling:alias` surprises:** an alias on `jcr:content` applies to the **parent**, and setting one on both **concatenates** rather than overrides; simple names only; an alias directly on a protected resource may be invisible to restricted principals (put it on a child). **Security — a vanity path can route around auth:** a child of a protected resource with an external vanity path or mapping that isn't a descendant of an existing authentication requirement fails to register that requirement; mitigate with external redirects or manual registration. Audit anywhere vanity paths are author self-service on a tree with protected branches. Vanity knobs (`vanitypath_allowlist`/`denylist`, `maxEntries` default unlimited, `vanity_precedence`, `sling:vanityOrder`) and alias perf knobs (`optimize_alias_resolution`, `allowed_alias_locations`). `$['env':'VAR';default='…']` interpolation works in `sling:match` (not node names) — one of the few per-environment seams when packages can't be environment-scoped. Namespace mangling `jcr:content`↔`_jcr_content`, registered prefixes only. **Test both directions at `/system/console/jcrresolver`** — a mapping that resolves is only half-verified. **Mirror of the trap (SLING-2560): a regex in `sling:internalRedirect` makes the entry reverse-only**, paired with a `$1/$2` `sling:match` — regex in match = inbound only, regex in internalRedirect = outbound only, two entries for both. `map()` yields an absolute URL only for wildcard-free entries (and, with a request, only when `Host` differs); only nodes with `sling:redirect`/`internalRedirect` are entries; URL replacements are re-fed through the table; `resource.resolver.mapping` = host-agnostic rules; page contradicts itself on `optimize_alias_resolution` (leave it on); node types are convenience, properties are what's read. Re-read Oct 2026.
- [url-resolution-layers-aemaacs.md](dispatcher-url-delivery/url-resolution-layers-aemaacs.md) — Which layer owns which URL rule on AEMaaCS: CDN → Apache `mod_rewrite` → Dispatcher → Sling resolver (mappings, aliases, vanity paths). Invariant to test: **`resolve(map(resource))` returns the same resource**. Testing only `resolve()` covers half the bugs. Apache should **normalise** (`RewriteRule ^/(en|es|fr)/(.*)$ /content/site/$1/$2 [PT,L]`) and not hold business routing rules. `PT` makes Dispatcher cache under the internal `/content` path, so AEM's repo-path flushes match. **The silent trap:** a cache keyed on the public path (`/es/courses/java.html`) is never invalidated by a `/content/...` flush, so pages go stale with no error. `sling:alias` renames a segment in both directions (localised slugs, node names kept stable across language trees for MSM/translation). A vanity path adds a separate shortcut: unique, no regex, must not collide with page paths, not a router. Dispatcher's `/vanity_urls` block (`/libs/granite/dispatcher/content/vanityUrls.html`, `/delay 300`) lets published vanity paths past a strict `/filter`. Build links, canonicals and sitemaps with `resourceResolver.map(request, path)` and never concatenate strings. `/content` paths in the sitemap mean outgoing mapping is broken. The `jcrresolver` Resolve/Map tester exists **only on the local SDK**. On AEMaaCS the Developer Console shows configs read-only with no tester, so reproduce on the SDK and trace from outside (response → rewrite log → HTML → canonical → sitemap). Source: Experience League Community article, Sept 2026, not reproduced.
- [exposing-apis-to-external-systems.md](dispatcher-url-delivery/exposing-apis-to-external-systems.md) — When a requirement has an external/third-party system calling an AEM API, the answer tier is always **Publish** (behind Dispatcher), never **Author** — Author is the writable, unpublished-content, internal-only system regardless of which auth scheme (OAuth/JWT, SAML, Basic Auth, IP allowlist) is chosen. Exam trap: a question can be framed as "third party hits the Author instance" and ask only which auth mechanism is safest — the real first-order architectural fix is to serve from Publish (or [brand-portal.md](assets-dam/brand-portal.md) for curated external-partner access), then pick the auth scheme for that Publish-tier endpoint.

- [duplicate-asset-detection.md](assets-dam/duplicate-asset-detection.md) — **Two unrelated duplicate-detection services, both real, different PIDs** (verified by disassembling bundles on 6.5 + AEMaaCS SDK): (1) `com.day.cq.dam.core.impl.servlet.CreateAssetServlet` → single Boolean `detect_duplicate` (default false), present on **both** 6.5 and cloud, sha1 field hardcoded, flags `dam:isDuplicateAsset` + returns `duplicates` in the upload response; AEM Guides' `com.adobe.dxml.upload.detectduplicate.DetectDuplicateService` reads that same PID and runs XPath `//element(*, dam:Asset)[(jcr:content/metadata/@dam:sha1 = '…')]`. - [content-type-classification-server-side.md](sites-content/content-type-classification-server-side.md) — Deciding whether a picked path is a **page, XF, content fragment or asset**, for anything that extracts or writes back per type. ## translation-i18n/

- [translation-rules-xml.md](translation-i18n/translation-rules-xml.md) — AEM `translation_rules.xml`: the config-as-code file (priority paths `/conf/global` → `/apps` → `/etc` → `/libs`) that AEM's Translation Configuration UI generates and custom connectors parse to decide translatability. Rule taxonomy: `<node path>` contexts (longest wins) holding `<property name translate inherit updateDestinationLanguage>` (name may be a **relative path** `image/alt`), `<node pathContains>` (path-substring exclusions), `<node resourceType>` (component-scoped, exact match, no super-type), `<filter>` node-skips (`containsProperty`/`propertyValue`/`isDeep` → `NON_TRANSLATABLE` vs `ONLY_CHILDREN_TRANSLATABLE`), plus top-level `<contentFilterNode>` (tag gate, e.g. `cq:tags=do-not-translate`). Defaults: property → excluded (opt-in), node → translatable (container the walk descends; prune only via `<filter>`); walk skips `cq:Page` children. **Key insight:** `<assetNode>` (`assetReferenceAttribute`+`resourceType`+`checkInChildNodes`+`createLangCopy`) is a **declarative, author-owned reference-finder registry** — one `/conf` XML line per referencing component instead of hand-coded Java reference finders (covers ~80%; component node plus, with `checkInChildNodes`, its untyped sub-nodes; rich-text/transitive/inherited refs still need custom code). The three custom connectors (translated.com, blackbird, LanguageWire) all parse this schema and none use `com.adobe.granite.translation.*`.
- [translation-connector-cached-services.md](translation-i18n/translation-connector-cached-services.md) — How to implement a translation connector's two JCR-backed hot-path services — the `translation_rules.xml` rules service and the cloud-config/credentials service — so their caches are correct on AEMaaCS. **A `ResourceChangeListener`-invalidated cache needs three mechanisms, not one:** (1) the `ExternalResourceChangeListener` marker, because AEMaaCS author is ≥2 pods on one repository and plain `ResourceChangeListener` "gets only local events" — an edit clears the cache on the writing pod only, so the rules report (routed request) and the XLIFF (Sling job, another pod) disagree, and nothing reproduces locally or on single-node on-prem; (2) an invalidation counter **sampled before the read** and stamped onto the cached value, because `updateAndGet` + `set(null)` loses an event that lands mid-read (a reader CASes null→stale onto an already-cleared cache); (3) a ~60 s TTL backstop for events never delivered at all. Registration traps: the marker does **not** extend `ResourceChangeListener` (implement both, keep registering under `ResourceChangeListener.class` — the marker alone deregisters the listener silently), and a listener with no `resource.paths` is ignored outright. Plus: no `synchronized` (AEM-15) — `AtomicReference` + `AtomicLong`; never cache the credentials failure fallback but do cache "no rules file" (cost: a 4-path `nodeExists` sweep per minute per pod); fetch the ruleset once per pass and thread it through the traversal; context-aware `/conf/<tenant>` lookup turns the cache into a keyed map whose invalidation must be global. Test recipe: aem-mock's `registerInjectActivateService` rejects a `now()`-overriding subclass (`NoScrMetadataException` → hand-wire with `FieldUtils.writeField`), the mid-read race is testable with zero threads via a one-shot `thenAnswer` that fires `onChange` during the load, and the marker needs its own `isAssignableFrom` guard test because nothing else can catch its removal. Implemented and unit-tested on the Crowdin connector, Sept 2026; translated.com's connector regressed the identical way.
- [cf-enumeration-translation.md](translation-i18n/cf-enumeration-translation.md) — CF Enumeration (dropdown) fields can't be marked Translatable **by design**: the stored value is a contract (model validation, GraphQL filters, facets) — translating it corrupts fragments (documented failure: framework sends the key, writes the translated string back, dropdowns stop resolving). The four handling patterns, ranked: (1) i18n dictionary at render time — stored value doubles as i18n key, HTL `@ i18n` or frontend key→label map; dictionaries themselves are translatable content (connector opportunity); (2) Tags instead of enum — `cq:Tag` titles localize natively; (3) custom datasource servlet — authoring-UI labels only; (4) key↔label workflow mapping — recommended by no one. A connector NOT serializing enum fields is correct behavior. Verified in core-components source: the CF component (`v1/contentfragment`) renders the raw stored key (dataType `string` → raw-print branch in `element.html`; model.json exports it raw too); cheapest fix = proxy-override `element.html` with `${element.value @ i18n}`. With Adobe/community source links. Researched July 2026.
- [i18n-dictionary-translation-target-path.md](translation-i18n/i18n-dictionary-translation-target-path.md) — A translated i18n dictionary **cannot be written beside its source**: `/apps` and `/libs` are immutable at runtime on AEMaaCS, so `/apps/myproject/i18n/de.json` is an unwritable target and fails at import time, after the vendor has already returned the translation. Adobe: the runtime translation process creates translated dictionaries in `/content/cq:i18n/<projectName>` *"regardless if the source dictionary is stored in /apps or /content"* — the source is only ever read, and Sling merges both locations into one `ResourceBundle`. Adobe's two tools disagree on the shape (translation projects drop `/i18n`: `/libs/wcm/core/i18n` → `/content/cq:i18n/wcm/core/zh.json`; the Translator mirrors the path: `…/search/i18n` → `/content/cq:i18n/…/search/i18n/ar`); lookup ignores the path, so mirror the full folder path, which cannot collide. **Precedence trap:** `/apps` beats `/libs` beats everything else, so a translation in `/content/cq:i18n` is silently ignored for every key a same-language `/apps` dictionary (e.g. a shipped `de.json`) already defines. Source text: often no source-language dictionary exists (keys are the English text; Adobe's "From dictionary keys" option); send `sling:message`, not the key, which the OOTB `.dict.xliff` export gets wrong (XLIFF 1.1, key in `<source>`). Merge into an existing target in its own format, keep target-only keys, copy `sling:basename`. **i18n is the one content type whose target does not mirror its source**, so a connector that reuses language-copy logic for it produces an unwritable path for every dictionary; likewise a classification rule scanning only `/apps` and `/etc` never sees the authorable dictionaries the Translator creates. Node shapes documented (JSON `nt:file`+`mix:language`, preferred since Sling i18n 2.4.2; `sling:Folder` with `sling:MessageEntry` children, or any child with the `sling:Message` mixin, which is what the Translator writes as `nt:folder`). Listing has no public API: the Translator's `translator.i18npaths.json` is one `mix:language` query grouped by parent. 6.5 differs (Translator edits under `/apps`, no `/content/cq:i18n` in its docs) but `/content/cq:i18n` is still correct there, since a deployment overwrites `/apps`. Adobe docs read Sept 2026; shapes verified on an AEMaaCS SDK author, 6.5 behavior not reproduced.
- [htl-i18n-page-language-gotcha.md](translation-i18n/htl-i18n-page-language-gotcha.md) — HTL `${'…' @ i18n}` resolves its locale as: explicit `locale` option → **containing `cq:Page` language** (`jcr:language` / locale path segment / default **en**) → request locale. - [osgi-import-package-version-range.md](java-osgi-build/osgi-import-package-version-range.md) — Fixing an OSGi bundle that won't start on AEM with `<package>,version=[X,Y) -- Cannot be resolved`: the `bnd-maven-plugin` version policy (`[==,+)`) turns whatever version is on the **compile** classpath into the emitted `Import-Package` range, so a transitive dep (e.g. an embedded SDK pulling commons-lang3 3.20) demands `[3.20,4)` while AEM only exports an older 3.x → resolution fails. Fix: override the import with `org.apache.commons.lang3.*;version=0.0.0` (bnd shorthand for "any version") so the bundle binds to AEM's platform-exported copy; the established pattern is to list every platform-provided lib (commons io/lang3/collections4, Granite/WCM, Sling APIs) with `version=0.0.0` plus a trailing `*`. Covers relax-range-vs-embed decision (`-includeresource ...;lib:=true` / `Private-Package` only for libs AEM does NOT export, e.g. jsoup), the **transitive-dependency trap** (embedding a jar makes ALL its transitive deps into imports — commons-lang3 is often just the first failure; repeat the fix down the chain), and the diagnostic recipe (`dependency:tree`, grep `MANIFEST.MF` Import-Package, Felix console Installed-not-Active = unresolved constraint). Opens with a **shopping-list model** for explaining the mechanism to a non-OSGi audience (the manifest is a shopping list; one unfillable line and the bundle doesn't start *at all*; two kitchens — 6.5 and Cloud — stock different versions; **unit tests cannot catch any of it**, since the list is only checked when a real AEM starts the bundle, so a 100% green build says nothing). Also covers the **removal** trap: an explicit `Import-Package` entry is FORCED into the manifest even when no class references the package, so deleting the code is only half a deprecation removal — the pom line must go too, and `grep` over `src/` looks clean while the manifest still demands it. Confirmed on the Crowdin connector `core` bundle (AEM SDK 2026.6, embedded SDK pulling commons-lang3 3.20), June 2026; and on the translated.com connector, Sept 2026, where the first use of `org.apache.jackrabbit.util.Text` emitted `[2.6,3)` — unsatisfiable on 6.5.23, which declares **2.5.0** for that package — while its sibling `org.apache.jackrabbit.commons` from the same library was already pinned `0.0.0`. Lesson: a pinned library does not protect its sibling packages, and a package's real version comes from its `package-info.class` `@Version`, not the artifact version.

- [java-target-platform-vs-build-jdk.md](java-osgi-build/java-target-platform-vs-build-jdk.md) — Targeting an old Java platform from a new build JDK. Untangles the axes people conflate: **build JDK** (21, runs javac) vs **target platform** (`--release 8`) vs **class file version** (52 = Java 8; 55/61/65 = 11/17/21) vs **runtime JVM** (JVM 8) vs the **JDK 8 class library** — correct phrasing is "compiled *with* JDK 21, *for* Java SE 8, runs on JVM 8+"; Java SE 8 == 1.8, so OSGi says `JavaSE 1.8` while `--release` takes `8`. Key rule: **`--release`, never `-source`/`-target` alone** — the latter pins language level and bytecode version but still compiles against the *build* JDK's library, so `List.of(...)` compiles clean at class file 52 and throws `NoSuchMethodError` on JVM 8; two failure modes with different symptoms (`UnsupportedClassVersionError` at class **load** vs `NoSuchMethodError` at first **call**), and a correct class file version proves nothing about API compatibility. Subtlest instance: Java 9+ compiles `"a"+x` to `invokedynamic`/**`StringConcatFactory`**, absent on JVM 8 → link failure despite a valid class file version; bites **generated** code you never wrote (Lombok `@Value` `toString()`), though `--release 8` restores the `StringBuilder` fallback (verified: Lombok 1.18.46 emits 0 StringConcatFactory refs at class file 52, with `@Value @Builder @Jacksonized @Slf4j @NonNull`). **Archetype trap:** AEM Project Archetype v56 hard-codes `<release>11</release>` on the compiler plugin, silently overriding `-Dmaven.compiler.release=8` — build says SUCCESS, emits 55; declare it as a property and read `${maven.compiler.release}`. Verification recipe (`xxd` class-file sweep incl. **embedded jars**, `javap -c` grep for makeConcat, manifest `osgi.ee=JavaSE 1.8`). Forward-compat caveats: class file 52 loads on every later JVM, but removed APIs still bite (JAXB/JAX-WS/CORBA gone in 11, `Thread.stop()` in 20, SecurityManager in 24, JDK-internal reflection denied from 16) and **CLDR became the default locale provider in Java 9** — so a translation connector must map locale labels from an explicit table, never from JDK display names. AEM note: classic 6.5 supports Java 8 *and* 11, so the floor is a customer question (6.5 LTS needs 17/21, AEMaaCS 11+). Verified on the Phrase connector, Sept 2026.
- [java11-bootdelegation-drift.md](java-osgi-build/java11-bootdelegation-drift.md) — `java.lang.NoClassDefFoundError: jdk/internal/reflect/ConstructorAccessorImpl` from Sightly's `JavaUseProvider` on AEM 6.5 under a Java 11 JVM = **not** a `pom.xml` problem and **not** an unsupported JDK (both are the plausible distractors); the instance's `org.osgi.framework.bootdelegation` in `crx-quickstart/conf/sling.properties` is still the Java 8 list. Java 8's reflection internals were `sun.reflect.*` (covered by `sun.*,com.sun.*`); Java 11 moved them to `jdk.internal.reflect.*`, which that list doesn't match. **Verified across three local instances (Sept 2026):** 6.5.0 GA (`...6_5_.20190328`) = `sun.*,com.sun.*` while demonstrably running OpenJDK 11.0.25; 6.5 LTS (`6.6.2.20260216`) and Cloud SDK (`2026.7.27083`) both = `sun.*,com.sun.*,jdk.internal.reflect,jdk.internal.reflect.*` (bare package **and** wildcard). `conf/` is instance state written at first unpack — **restarting under JDK 11 does not heal it** (file is rewritten each start, stale value persists), and no `sling.bootdelegation.<x>` conditional entry keys `jdk.internal.reflect`, so nothing notices the JVM changed. Drift sources: reused `crx-quickstart` after a `JAVA_HOME` switch, in-place SP (never regenerates `conf/`), hand-edited `sling.properties` (won't be clobbered — looks current, isn't), cloned/golden-image envs (common on AMS), `-D` override in a copied start script. **Why it slips past testing:** boot delegation is consulted lazily (everything resolves and starts clean) *and* HotSpot serves the first ~15 reflective calls with a native accessor before generating the bytecode one that extends `ConstructorAccessorImpl` — so the component renders fine several times, then starts throwing, looking intermittent/load-related. Fix is `sling.properties` + restart, never the build; fleet triage: `grep -H '^org.osgi.framework.bootdelegation' */crx-quickstart/conf/sling.properties`.

- [all-package-embed-structure.md](java-osgi-build/all-package-embed-structure.md) — The **assembly layer** of an AEM Maven project, i.e. everything past the well-known four-package split. Embed `<target>` is a fixed four-level grammar `/apps/<app>-packages/<application|content|container>/install[.author|.publish]` — level 3 is a *type* folder dictated by the embedded package's `packageType`, level 4 accepts **only** those two run-mode suffixes (you can scope OSGi config per environment, never a package embed), and the container's `definition/filter.xml` must cover the embed root or the zips build in and never install. The **`-packages` suffix is load-bearing**: without it the installer can treat subpackages as installables of the app it is installing → destructive cyclic installation, and nothing validates the name. Subprojects need `<cloudManagerTarget>none</cloudManagerTarget>` so only `all` deploys. **`ui.apps.structure`** is mandatory for every `packageType: application` and *not* for `content` — it is a build-time proof that no code package installs over another (and is why overriding the filter validator's `validRoots` doesn't break `/apps`). **The dependency trap:** a code package holding only OSGi bundles must NOT be declared as a dependency — bundle-only packages aren't registered with Package Manager, so it can never be satisfied and the symptom reads like a version mismatch on an artifact that demonstrably built. `ui.config` is `packageType: container` (corrected Oct 2026 — the validator forbids OSGi config/bundles in `application` packages; see filevault-package-types.md) rooted at `/apps/<app>/osgiconfig`. Vendor connectors ship their own `all`, embedded by the customer at the shared `/apps/vendor-packages/container/install` — so every package nested inside a vendor artifact must satisfy the cloud guidelines or it fails *the customer's* deploy, unfixable from their side. Plus: one package can't span `/apps` and mutable roots, containers can't use install hooks, Oak indexes ship as code because reindex precedes image switchover.
- [vendored-all-package-audit.md](java-osgi-build/vendored-all-package-audit.md) — Before embedding a vendor/sample `all` on AEMaaCS, **unpack it recursively**: the build stays green while problems hide 2–3 levels down. Look for: a bundled **`core.wcm.components.all`** (old bundle + `/apps/core/wcm/components` overriding the platform's 2.30.x for every site; the analyser only *warns*), `/etc/packages` nesting, an `application`-typed `all` that is really a container, run-mode-less `debug` log configs (WKND SPA 1.0.3 = half of a 325 MB/day dev log), single-instance configs another package also sets (more specific run mode silently wins), `.content.xml` not starting with `<?xml`. Re-vendor recipe: subpackages one by one in a file-based local repo; **suffixed Maven version** on any change, keep or change the **package version inside** based on who depends on it; each container gets its own filter root; re-audit the built output.
- [filevault-package-types.md](java-osgi-build/filevault-package-types.md) — The four `<packageType>` values with their validator-enforced content rules: `application` = `ui.apps`, immutable `/apps` code, **may NOT contain OSGi configs or bundles**; `content` = `ui.content`, mutable `/content`+`/conf`, nothing under `/apps`; `container` = `all` **and `ui.config`**, embedded sub-packages + OSGi bundles/configs (installer payload); `mixed` = legacy, no guarantees, avoid. The split people get wrong: mutable-vs-immutable only separates `content` — within immutable the line is **JCR code vs OSGi-installer payload**, and installer payload is `container`-only. **Exam trap:** "module for run-mode configs" → `ui.config` → `container`; `application` is the planted closest-wrong answer (intuition "config is immutable code under /apps" — but the validator rejects it, locally and in Cloud Manager's Build step); `content`/`/conf` is wrong twice (configs aren't authorable; a `.cfg.json` under `/conf` is dead content). Type routes the AEMaaCS deployment path (immutable image vs mutable install — mixed packages half-install silently, see rolling-deployment doc). Verified `<packageType>container</packageType>` in the archetype's ui.config pom (GitHub, Oct 2026); supersedes the `application` claim formerly in all-package-embed-structure.md.
- [httpclient-retries-timeouts-aem-connector.md](java-osgi-build/httpclient-retries-timeouts-aem-connector.md) — Apache HttpClient 4.5 is exported by **both** `aem-sdk-api` and `uber-jar` 6.5.22 (verified `unzip -l`, Sept 2026), so a connector needs no vendored HTTP client, just `org.apache.http.*;version=0.0.0` in bnd. **Do not hand-roll the retry loop:** `HttpRequestRetryHandler` covers connection failures (extend `DefaultHttpRequestRetryHandler` so its exception and idempotency rules still apply; with the default `requestSentRetryEnabled=false` a POST is replayed only if it never reached the server, which is what stops a token exchange being submitted twice) and `ServiceUnavailableRetryStrategy` covers `429`/`5xx`; never retry `4xx`. Both are configured per *client*, so a per-call policy (interactive = one attempt, poller = retries) travels in `HttpClientContext` attributes, which both `retryRequest` overloads receive. **The trap:** `getRetryInterval()` takes no arguments — no response, no context, no execution count — so `Retry-After`, exponential backoff and per-call intervals are all inexpressible without smuggling a value through a `ThreadLocal` set in `retryRequest`; decide deliberately, a fixed interval is often fine. **Timeouts are not a ceiling:** connect and read are separate and additive (5+10 = a 15 s call), and the socket timeout is per *read*, so a trickling response runs indefinitely; 4.5 has no total-call timeout and a real one needs a watchdog calling `request.abort()` — which is allowed where `Future.cancel(true)`/`shutdownNow()` are not, since `CQRules:GRANITE-54181` bans interrupting threads, not closing sockets. **Anti-pattern with its own section:** splitting one deadline across two sequential calls (call 1 takes the budget, call 2 gets the leftovers and times out) makes a healthy connection report "did not respond" and throws away an already-successful call; give each call the same timeout instead. Plus the OSGi lifecycle (`@Activate`/`@Modified`/`@Deactivate`, `volatile` client read once per call). From the Phrase TMS connector.
- [sling-path-matches-relative-throws.md](java-osgi-build/sling-path-matches-relative-throws.md) — `org.apache.sling.api.resource.path.Path.matches(other)` is the right "equal to or below" check (`/content-other` false, `new Path("/")` matches everything) but **throws `IllegalArgumentException: Path must be absolute` on a relative argument** instead of returning false, and `ResourceUtil.normalize` keeps relative paths relative. Swapping a hand-written prefix check for it turns a clean 400 on `path=content/acme` into a 500. Fix: check absoluteness at the request boundary before `matches`; keep a relative-path case in the servlet's reject test. Phrase connector, Sept 2026.
- [server-sent-events-in-aem.md](java-osgi-build/server-sent-events-in-aem.md) — Pushing live updates to an author console without polling. AEM does not buffer an SSE response: `text/event-stream` plus `writer.flush()` and `resp.flushBuffer()` per frame streams immediately, chunked. A resource-type-bound servlet answers on any extension (`.sse`), and the login-token cookie carries auth since `EventSource` cannot send headers. Cost is exactly one parked Jetty request thread per stream (measured 1:1), which also holds a JCR session, so cap streams or use `startAsync()`. The trap: a loop with no lifecycle exit survives a bundle stop *and* restart, orphaned forever while keepalives make it look healthy — needs an `@Deactivate` flag (not an interrupt, banned by CQRules:GRANITE-54181) plus a duration cap. Reconnection is weaker than advertised: a non-200 permanently closes `EventSource`, so a redeploy's 404 kills the page until the client implements its own backoff retry. For a dashboard, one channel with a named-event envelope (`name`/`data`/`terminal`) and a bounded queue per subscriber using `offer`, never `put`. On multi-pod AEMaaCS author an in-memory publisher only reaches its own pod's streams: publish from a JCR `ResourceChangeListener` with the `ExternalResourceChangeListener` marker instead.

- [openai-function-calling-responses.md](ai-integration/openai-function-calling-responses.md) — The OpenAI function-calling contract, Responses-API mode, for agent loops on the raw SDK. **The loop:** request with `tools` → `function_call` items in `response.output` (assume zero/one/many, even of the same function) → you execute → send `function_call_output` items → final text or more calls; nothing executes server-side. **Shape traps:** Responses tool defs are **flat** (`type/name/description/parameters/strict` top-level) while Chat Completions nests them under `function:` — porting examples across silently mismatches; each call item has **two ids** (`id` = `fc_…` item id, **`call_id` = `call_…` is what you echo**); `arguments` is a JSON-encoded *string*, `json.loads` it. State between requests: append the **entire** `response.output` to the running input (reasoning models' reasoning items **must** be passed back with the outputs) or use `previous_response_id` + just the output items; `output` is a free-format string (or image/file array; `"success"` for void), results may return in any order via `call_id`. **Strict-mode default divergence:** explicit `strict: true` + bad schema = loud rejection, but **omitted on Responses = silent normalization attempt with fallback to best-effort** (tell: `strict: false` echoed on the tool), omitted on Chat Completions = always non-strict; same enforcement asymmetry as [llm-structured-output-contracts.md](ai-integration/llm-structured-output-contracts.md) (structure+enums locked, ranges not); fine-tuned models cache schemas (no ZDR) and drop strict on parallel calls. **tool_choice**: auto/required/forced/none + `allowed_tools` to restrict the callable subset *without* touching the `tools` list (keeps prompt cache warm); `parallel_tool_calls: false` = zero-or-one call. Design: the **intern test**, enums make invalid states unrepresentable (`toggle_light(on,off)` counterexample), never make the model fill args you already know, merge always-sequential functions, ~20-function soft ceiling (definitions bill as input tokens every request), examples may hurt reasoning models. Streaming: `output_item.added` → `function_call_arguments.delta` (accumulate by `output_index`; parseable only at `done`) → `output_item.done`. Plus one-paragraph notes on namespaces/`defer_loading`, `tool_search` (gpt-5.4+), and custom tools (free-text `input`, optional Lark/regex CFG `format`). Docs-based Oct 2026.
- [llm-structured-output-contracts.md](ai-integration/llm-structured-output-contracts.md) — How an LLM decides what to put in each field of a declared schema, for assistants that must hand validated objects to AEM/Java code instead of prose. **The form model:** three distinct channels — field *names* are the actual specification (a box called `summary` needs no explanation; call it `xyz` and you get garbage), per-field `description` is read at the moment that field is generated (right place for field-local rules like "quote verbatim"), and `instructions`/`input` carry cross-field policy and the facts. **The trap worth internalizing:** with `strict: true`, constrained decoding enforces only *structure* — required keys, `additionalProperties: false`, types, and **`enum` members** (a `Severity` field genuinely cannot return `"sev-1"`) — while range/length keywords are sent in the payload but **not decoder-enforced**; `minItems`/`minimum`/`maximum` are hints, and Pydantic catches violations client-side *after* the call, meaning `responses.parse()` can raise `ValidationError` from inside, so a wrapper guarding only the `None` case is incomplete. Put guarantees you depend on in enums and types; re-check every numeric range in code. **Field order is generation order** — declare `confidence` last so the model scores certainty *after* committing to a cause, not before. **Schema-shaped hallucination:** a required non-empty list (`suggested_actions` with `min_length=1`) instructs the model to invent a remediation step when the context supports none — leave it unconstrained and render the empty case explicitly; keep `min_length=1` only where the caller always supplies enough context to cite (`evidence`). Also: `output_parsed` is `Optional` (raise, don't widen the return type), dump `to_strict_json_schema(Model)` before debugging a prompt, and remember valid ≠ correct — schema validation moves the failure from *unparseable* to *parseable and possibly wrong*, and `confidence` is a self-asserted signal, not a calibrated probability. Verified openai 3.8.0 / pydantic 2.13.5 / Python 3.13, Sep 2026.

## network/

General networking fundamentals (IP, MAC, ARP, MTU, checksums) plus tools and diagnostics (traceroute, ICMP, ifconfig, tcpdump), each ending in what they can and can't tell you about AEM.

- [traceroute.md](network/traceroute.md) — How traceroute works (TTL expiry → ICMP "time exceeded" from each hop) and how to read it. **Probe protocol first:** macOS/Linux default is UDP, and **a UDP trace to Adobe's Fastly CDN (`151.101.3.10`) shows `*` to the hop limit even though the site is up**, while `-I` (ICMP) reaches it in 5 hops; TCP (`-P tcp -p 443` on macOS, `-T` on Linux) matches HTTPS but **needs root** (`pcap_activate() failed` without sudo). Reading the output: `* * *` mid-path with later hops answering = silent router, not loss; a high mid-hop time that doesn't persist = slow router CPU path, ignore it; only latency/loss that **persists to the destination** counts; ECMP, hidden MPLS hops, asymmetric return paths. `-a` shows AS owners (where the ISP hands off to Fastly AS54113), `-n` skips reverse DNS; `mtr -rwzc 100 -T -P 443` for intermittent problems. **AEM:** Fastly IPs are anycast, so an AEMaaCS trace stops at the nearest POP and says nothing about CDN→origin; use it only for "does the domain reach Adobe's CDN" (after `dig`) and "is slowness before or after the edge"; Cloud Manager allow lists are enforced at the CDN, so a blocked office traces cleanly and gets a 403 (debug with `curl -sv`); on AMS/on-prem, trace with TCP on the real port (4503, backend ports), because firewalls make UDP/ICMP traces fail on working paths. Verified macOS traceroute, Oct 2026.
- [icmp.md](network/icmp.md) — ICMP in plain terms: messages *about* packets (the post office "return to sender" stamp), carried on IP with **no ports and no connections**, generated by kernels and routers, so firewall rules are by **type/code** not port. Types that matter: Echo 8/0 (`ping`), **Destination Unreachable 3** (code 3 port unreachable = how UDP traceroute finishes; **code 4 fragmentation needed = Path MTU Discovery**), **Time Exceeded 11** (= traceroute), Redirect 5 (ignored by modern OSes), Source Quench (obsolete). **Header anatomy**: Type / Code / Checksum (IPv4 checksum has **no pseudo-header**, ICMPv6 does) + 4 type-specific bytes (Echo id/seq; **next-hop MTU** for type 3 code 4; Redirect gateway) + data; every error quotes the original IP header + ≥ 8 bytes (visible in macOS `ping -m N` output) so the sender's OS can match it to a socket and NAT can translate it — minimal error = **36** ICMP bytes, default echo = **64** (56 data). ICMPv6 renumbers (Unreachable 1, Packet Too Big 2, Time Exceeded 3, Echo 128/129) and **< 128 = error, ≥ 128 = informational** for one-rule firewall policies. Storm rules: no error in reply to an error, none for broadcast/multicast, rate-limited → **silence is ambiguous**. Verified readings of silence: Fastly *does* answer ping (~23 ms) while most hardened hosts don't; `nc -u -z … succeeded!` means only "no Port Unreachable arrived"; **`sendto: Message too long` on `ping -D` is the local kernel's MTU check, not the network**. **PMTUD / TCP / MTU black hole** = handshake works, `ping` works, anything large hangs → firewall dropping type 3 code 4; fix by allowing it, MSS clamping, or `tcp_mtu_probing`. **Never block all ICMP**: block Echo only; always pass type 3 (esp. code 4), 11, and all ICMPv6 Neighbor Discovery + Packet Too Big or IPv6 dies. **AEM:** ping to `cdn.adobeaemcloud.com` proves only edge reachability (allow lists are HTTP 403, origin invisible); on AMS test TCP on 4503/443, not ping; author→publish or Dispatcher→publish over VPN/tunnels that connect but stall on large packages = PMTUD until proven otherwise; health checks and content-request billing are HTTP-only. Verified macOS, Oct 2026.
- [arp.md](network/arp.md) — ARP via the names-and-faces picture: broadcast "who has X?" on the local segment, unicast reply, cached with a timer; own EtherType `0x0806`, **not inside IP** (works before DHCP, invisible to IP firewalls), never crosses a router (off-subnet = ARP for the gateway). **Gratuitous ARP** (unsolicited announce, how failover works) and **ARP probe** (`0.0.0.0` sender, duplicate detection) are the two variants that matter. macOS cache defaults: `max_age` **1200 s**, `prune_intvl` 300 s, `arp_llreach_base` 120 s, `maxtries` 5, **`log_arp_warnings` 0 by default** (MAC flips are silent), `arp -a` drops leading zeros; Linux re-resolves in ~60 s and `arp_accept=0` still *updates* existing entries. **Diagnostic use:** `arp -a` shows the MAC a host is really sending to; "ping works but connection hangs" / "one Dispatcher cannot reach one publisher" → compare MACs on both sides first; **stale ARP after failover** = new host unreachable from one neighbour until the timer expires (`arp -d` to clear, gratuitous ARP to prevent). **ARP poisoning** (own section): an on-segment attacker sends unsolicited replies claiming the gateway's IP to the victim and the victim's IP to the gateway, forwards traffic so nothing breaks, and repeats every few seconds to beat re-resolution → reads/alters/drops anything not end-to-end encrypted, attacks TLS only via a fake cert (fatal only if the client clicks through or uses `-k`). Spot it: **two IPs sharing one MAC**, gateway MAC changed, hop 1 in traceroute wrong, surprise cert warnings. Defences ranked: TLS everywhere → client isolation on guest Wi-Fi → **Dynamic ARP Inspection + DHCP snooping** on managed switches → static `arp -s` for the gateway on critical hosts → `arpwatch`/IDS to know it happened; failover and poisoning look identical from one host, so check whether a failover just happened and whether the new MAC is a server you own. **AEM:** irrelevant on AEMaaCS beyond your own office LAN (TLS to Adobe defeats it); on AMS/on-prem the surface is **plain-HTTP internal hops** (Dispatcher→4503, replication, author 4502 from an office LAN) leaking replication Basic-auth and `login-token` cookies → terminate TLS on publish, isolate the AEM VLAN, static ARP on Dispatcher/publish.
- [ip-addresses.md](network/ip-addresses.md) — IP addresses via the mailbox picture: an IP is "where to send the letter" (and the return address); DNS is the phone book (A = name→number, CNAME = alias, **apex can't be a CNAME** — why Cloud Manager wants four A records for bare domains but a CNAME for subdomains); private ranges (`192.168.*`, `10.*`, `172.16–31.*`) are room names that don't route outside, NAT is the receptionist, so one office = one public IP = feasible allow lists; **IP allow list = doorman's guest list**, canonical failure = a legitimate service turned away with the burglars (Screens starved by a publish allow list); **CIDR**: `/24` = 256 addresses not 24, smaller suffix = bigger block, `/32` = one; IPv4 (~4.3 B, exhausted, hence NAT) vs IPv6 (`AAAA` records — an IPv4-only allow list treats IPv6 clients differently, silently); IP delivers letters, TCP makes them a conversation, **ports are apartment numbers** (`:443`, `:4502`, `:8023` standby sync) — IP+port is the full address.
- [mac-addresses.md](network/mac-addresses.md) — Both MACs. **MAC address** via the mailbox-name picture: 48-bit link-layer id, **OUI prefix = vendor**, **second-lowest bit of byte 1 = locally administered (`x2/x6/xA/xE`)**, `ff:…:ff` broadcast; lives **only on the local segment** (routers rebuild the frame per hop, servers/CDNs/licence servers never see a client's MAC); IP→MAC via **ARP** broadcast or **ICMPv6 Neighbor Discovery** (so blocking ICMPv6 kills IPv6). Verified on a 2026 consumer Wi-Fi LAN: **every client except the router used a randomised MAC** (iOS 14+/Android 10+/macOS Sequoia+ per-network randomisation) → MAC allow lists, MAC-keyed DHCP reservations, captive portals and MAC-bound licences break "randomly"; spoofing is one command, so never a security control; macOS `arp -a` drops leading zeros. Outages it causes: **stale ARP after failover/re-IP** (new host unreachable for exactly the cache lifetime unless gratuitous ARP), **duplicate MACs on cloned VMs** (switch table flaps, intermittent reachability). **AEM:** Dispatcher losing a publisher for minutes after failover = stale ARP; **AEM 6.x licences are NOT MAC-bound**; AEMaaCS nothing (allow lists are IP at the CDN); don't implement "office only" author access via Wi-Fi MAC. **Message Authentication Code** = keyed integrity tag (HMAC; what a checksum isn't; folded into AEAD in modern TLS): AEM's **encapsulated token** is an HMAC, so the `hmac` key (with `master`, default on filesystem under `crx-quickstart/launchpad/felix/bundle<N>/data` since 6.3, `/etc/key` is the old repo location) **must be identical on every publisher** or logins bounce between nodes and `{…}` encrypted configs fail to decrypt on clones. Oct 2026.
- [mtu.md](network/mtu.md) — MTU via the bridge-height picture: the largest **IP packet** a link carries (Ethernet frame header excluded, IP+TCP headers included), **path MTU = lowest bridge on the route**, and the sender only learns of a low bridge if ICMP comes back. Values: **1500** Ethernet/Wi-Fi, 1492 PPPoE, 1476 GRE, ~1400–1440 VPNs (WireGuard 1420), **1280 IPv6 floor**, 9000 jumbo (one admin domain only, never the public internet — why 1500 survived 40 years), loopback 16384 macOS / 65536 Linux. **MTU is a link property, MSS is what TCP negotiates** from each side's *own* interface (1460 v4 / 1440 v6), neither knows the path → PMTUD. **Largest 1500-fitting ping = 1472 data bytes** (20 IP + 8 ICMP); 1473 fails locally with `sendto: Message too long` (own kernel, not the network). Oversize: IPv4 fragments unless DF set, **all modern TCP sets DF**, **IPv6 never fragments in transit** (ICMPv6 Packet Too Big only); filtered ICMP = PMTUD/TCP black hole (→ icmp). Probe recipe (`ping -D -s N` step-down, `tracepath`, `ifconfig … mtu`): a reply proves path MTU ≥ N+28, a timeout proves nothing alone. Classic tickets: VPN client browses but can't upload, jumbo VPC vs 1500 interconnect, VXLAN overlay (−50 bytes) pods hang on big responses, PPPoE homes vs the office. Fix order: pass ICMP → **MSS clamping** on the tunnel → `tcp_mtu_probing` → lower interface MTU last. **AEM:** replication/Dispatcher/asset uploads across a tunnel that stall above a size threshold = MTU until proven otherwise; AEMaaCS customers own only the *customer* end of advanced-networking VPN/dedicated egress MTU+MSS; verified full 1500-byte DF packets reach Adobe's Fastly edge, so client-side stalls on AEMaaCS sites are the client's tunnel. Verified macOS, Oct 2026.
- [internet-checksum.md](network/internet-checksum.md) — What a checksum is (the "digits add up to 47" phone-line picture: detect corruption, never fix it, never security) and the one RFC 1071 recipe shared by IP/ICMP/TCP/UDP: **16-bit words, ones-complement sum with end-around carry, bitwise invert; receiver sums everything incl. the field and expects `0xFFFF`** (worked `0x4500+0x0054 → 0xBAAB` example + Python). Design trade-offs: cheap and **incrementally updatable** (TTL decrement, NAT rewrites patch it arithmetically, RFC 1624), **order-blind** (swapped words undetected), catches all single-bit errors but not cancelling pairs; Ethernet CRC-32 is the strong one, TLS/IPsec provide integrity. Coverage table: **IPv4 header only** (re-done per hop); **ICMPv4 whole message, no pseudo-header**; **TCP/UDP message + pseudo-header** (src/dst IP, proto, length — catches wrong-host delivery), **UDP optional on v4 (`0` = none, computed 0 sent as `0xFFFF`)**; **IPv6 has no header checksum**, transport + ICMPv6 checksums mandatory with v6 pseudo-header. Gotchas: NAT must patch the ICMP checksum when rewriting the *quoted* inner IP header of an error or hosts drop every ICMP error (looks like a PMTUD black hole); **"checksum incorrect" on your own outgoing packets in tcpdump/Wireshark = NIC checksum offload, not a bug**; mismatches are silent drops (TCP retransmits, UDP/ICMP just lose), so a corrupting link shows as unexplained retransmits, never an error; VXLAN/tunnel checksum stripping = "works on v4, breaks on v6". AEM: nothing to configure; read captures with offload noise in mind, capture both ends to separate corruption from PMTUD, content integrity is TLS. Oct 2026.
- [ifconfig.md](network/ifconfig.md) — Reading one interface block: **`UP` = enabled, `RUNNING` = link; `UP` without `RUNNING` is the unplugged cable**, `status: active/inactive` is carrier; **macOS prints the netmask in hex** (`0xffffff00` = `/24`, `0xfffffe00` = `/23`, use `-f inet:cidr` to stop converting); `ether` = MAC, `inet6 fe80::` exists on every interface and is not "IPv6 in use", `%en0` is the zone, `secured`/`temporary` are privacy addresses; `options=TSO/CSUM` offloads are why **captures on the same host show bad checksums and over-MTU segments**; `media` shows negotiated speed/duplex (half-duplex on a server = autoneg failure). Forms: `-l`/`-lu` names, `-v` link quality and `type: Wi-Fi`, `-a` on Linux to include down interfaces; changes (`up/down`, `mtu`, `alias`, `ether`, `promisc`) need root, **do not persist**, and bouncing the interface you are SSH'd over locks you out. macOS cannot tell you which `en` is Wi-Fi: `networksetup -listallhardwareports`, `route -n get default` (a `utun` there = VPN path, changes MTU/source IP/DNS); companions `ipconfig getifaddr|getpacket en0` (DHCP lease fields), `netstat -rn -f inet`, `netstat -i` (growing `Ierrs/Oerrs/Coll` = layer 1), `scutil --dns`; `169.254.x.x` = DHCP failed. Linux: `ip addr|link|route`, `ip -s link`; net-tools `ifconfig` hides secondary addresses. **AEM:** nothing on AEMaaCS beyond knowing which path your browser/pipeline takes before blaming an allow list; on AMS/on-prem the first command on a host that "cannot reach X": mask mismatch (`/23` vs `/24` reaches half the segment), MTU hypothesis test with `ifconfig <if> mtu 1400`, NIC error counters behind intermittent 502s, which node holds the VIP alias after failover; AEM's own listen address is a Felix HTTP property, not an ifconfig matter. Verified macOS, Oct 2026.
- [tcpdump.md](network/tcpdump.md) — `sudo tcpdump -i <if> -nn [-c N] [-w f.pcap] '<filter>'`, read back with `-r` (no root). **Root needed to capture, and on macOS even `-d` (compile filter only) fails without root** (`SIOCIFCREATE: Operation not permitted`, Apple's pktap) → test filters with `-d -r file`; `tcpdump -D` lists interfaces + association state without root; **macOS has no `-i any`**: `-i pktap,en0,lo0` or `-i all` (pcap-ng, not promiscuous, `-k` adds process name/PID). Always `-nn` (reverse-DNS stalls, wrong `/etc/services` names for AEM ports) and `not port 22` over SSH; wrong interface = empty capture (`localhost` is `lo0`, VPN is `utunN`, Dispatcher→publish on one host never hits the NIC). BPF grammar table (`host/src/dst/net/port/portrange`, `tcp[tcpflags] & (tcp-syn|tcp-rst) != 0`, DF bit `ip[6] & 0x40`, ICMP errors `icmp[0] != 8 and != 0`, TLS ClientHello byte test) — filter at capture time, not on the 2 GB file. Reading lines: `Flags [S]`/`[S.]`/`[.]` = handshake, **`[S]` repeating = dropped, `[S]` then `[R.]` = closed port**, `[P.]` = data, `win 0` = receiver not reading (AEM thread stall shows here first); **`seq/ack` are relative only if the SYN was captured — a PSH-only filter prints absolute numbers (verified)**, `-S` forces absolute; `-v` adds TTL/DF/`cksum (correct|incorrect)` and **incorrect checksums + over-MTU `length` on packets the capturing host *sent* are NIC offloading, not faults**; `-A` shows plain HTTP incl. `Cookie: login-token` and Basic auth (capture files are secrets), TLS shows only SNI; `-e` MACs, `-tttt` log-matching timestamps, `-G`/`-C -W` rotation, `N packets dropped by kernel` = tighten the filter. **AEM:** on AEMaaCS only "does TCP+TLS to the CDN complete" (403 vs network); on AMS/on-prem capture on the Dispatcher toward 4503: `/renders` wrong IP (`[S]` unanswered or `[R.]`), slow publisher (instant ACK, late `HTTP/1.1 200`) vs slow network (late ACK, retransmits), PMTUD black hole (large `[P.]` retransmitted, no need-to-frag), which headers Apache really forwards (`-A`), replication `POST /bin/receive` responses; local SDK author = `-i lo0 port 4502` to see raw requests, cookies and `CSRF-Token`. Verified macOS tcpdump 4.99 reading a synthetic capture, Oct 2026.

## system-design/

General (non-AEM) system-design reference: patterns, trade-offs, and failure modes, each linking to the AEM instance of the concept where one exists.

- [api-design.md](system-design/api-design.md) — REST/pagination/idempotency/versioning/rate-limiting field guide. Methods by contract (**PATCH not idempotent unless made so**; 200-with-error-body breaks every generic retrier); offset pagination = O(offset) + drift under writes vs **keyset cursors** (opaque, unique+immutable sort key, tie-break with id); idempotency = design for the duplicate (**timeout tells the caller nothing**) via idempotency keys written **in the same transaction** as the side effect, same-key-different-body → 422; versioning: path versioning wins, the real discipline is tolerant readers + **unknown-enum-value fallback** (the classic silent break) + `Sunset` headers with per-client telemetry; rate limiting: token bucket, `429`+`Retry-After`+`RateLimit-*` headers, choose the key (per-IP breaks behind NAT, per-tenant is the real goal), local-only counters × node count, retries without jitter = synchronized storm.
- [caching.md](system-design/caching.md) — Layers (browser cache is uncontrollable after shipping → content-hash filenames), `Cache-Control` semantics (**`no-cache` = revalidate, not don't-store**; `stale-while-revalidate`/`stale-if-error`), **`Vary: Cookie` shatters the hit rate**, surrogate-key purge > URL purge; cache-aside + the **stale-write race** (reader writes pre-update value after the invalidation → rule: **delete, don't update**); stampede/penetration/avalanche/hot-key fixes (single-flight, jittered TTLs, negative caching, L1-in-front); Redis `noeviction` default **rejects writes when full**; staleness budget per data class in writing; verify behavior with the cache empty *and* down. AEM: Dispatcher+Fastly = two caches to purge.
- [async-systems.md](system-design/async-systems.md) — Work queues vs event logs (imperative-named "event" = command in disguise); Kafka in five: **ordering only within a partition** (key→partition), consumer-group parallelism capped by partition count, commit-after = at-least-once (exactly-once = at-least-once + idempotent consumer), **head-of-line blocking** (the mechanics of AEM's blocked distribution queues), rebalance storms from slow poll loops; retries: classify errors (untyped catch-retry = storm root), **backoff with full jitter**, retry budgets vs 27× amplification, delay-topics not sleeping consumers; **DLQ without alerting+replay+owner = write-only graveyard**, replay is out-of-order; dual-write problem → **transactional outbox**/CDC; consumer lag is the health metric; queues add time not capacity; big payloads → pass blob references.
- [scalability.md](system-design/scalability.md) — Scaling is a **state-placement problem**: vertical first for stateful things, horizontal only as linear as the coordination is absent (USL: throughput can *decrease* past a point); stateless checklist (sessions/files/jobs out of the instance; **sticky sessions are a confession**; warm-container "persistence" vanishes under scale-out); L4 vs L7 LBs, least-connections vs round-robin, **readiness checks that call shared deps take the whole fleet out**, connection draining; autoscale on leading metrics (latency-only oscillates), scale-out must outrun the ramp, **scaling the tier in front of a fixed DB converts slowdown into DB outage**, per-instance pools × N = connection exhaustion → pooler. AEM: publish farm = the pattern executed; TarMK author = the stateful counter-case.
- [data-storage.md](system-design/data-storage.md) — SQL-vs-NoSQL by real axes (query flexibility, consistency, scaling, schema enforcement point); default Postgres, NoSQL is **access-pattern-first** design (new query pattern = the standard regret); B-tree **leftmost-prefix rule** (equality columns before the range column; functions/leading-wildcards/type-casts silently bypass), covering + partial indexes, every index taxes writes; replication: async lag → failover **loses acknowledged writes**, read-your-own-writes fixes (leader pinning, min-LSN tokens), untested failover ≠ HA, **LWW silently drops data** (clock skew picks the winner), replication ≠ backup (replicas replicate your DELETE); consistency: CAP only during partitions (PACELC otherwise), design invariants *inside* one atomic unit, sagas = visible intermediate states.
- [reliability-patterns.md](system-design/reliability-patterns.md) — Cascades are self-inflicted: **library-default (infinite) timeouts** pin worker threads until the caller dies of the callee's slowness; connect vs read timeouts from measured p99, **deadline propagation** (inner timeout > outer = wasted load + masked errors), timeout = ambiguous outcome → idempotency; retry at ONE layer + retry budgets vs 27× amplification; circuit breakers (closed/open/half-open, per-endpoint, min volume, **retries hammering half-open reopen it forever**, open-circuit behavior is a product decision), bulkheads per dependency; **backpressure**: Little's Law — unbounded queue = overload converted to unbounded latency + OOM delivered during recovery; bound everything, shed at the edge, pre-decide shedding order; **metastable failure**: goodput stays collapsed after load normalizes — autoscaling can't outrun it. Untested fallback = second bug behind the first.
- [observability.md](system-design/observability.md) — Metrics/logs/traces by job: **cardinality is the metrics cost model** (user-id label = TSDB death), structured one-wide-event-per-request logs, traces need context propagation through queues too, **tail sampling** keeps errors+slow; `trace_id` in logs or you own three silos; RED/USE, **never average percentiles** (merge histograms), instrument the caller, breaker-state = leading indicator; **alert on SLO burn-rate, not causes** (14.4×/1h page, 3×/6h ticket), every page actionable-and-urgent; SLI→SLO→SLA chain, **error budget converts reliability into a resource** (no spend-policy = wall poster), measure at the user boundary, segment per-tenant ("0.1% of users fail 100%"); telemetry cost curve (logs ≫ traces ≫ metrics), absence of telemetry is itself a signal (deadman switches).
- [security-auth.md](system-design/security-auth.md) — OAuth = delegated authz, **OIDC adds the ID token** (never send it to APIs); Auth Code+PKCE everywhere user-facing (implicit is dead), client credentials for S2S; resource-server validation: signature+`iss`+**`aud`** (cross-service replay)+`exp`, reject `alg:none`; **JWT revocation doesn't exist** → short tokens, revoke at refresh (rotate refresh tokens, reuse-detection reveals theft); RBAC: check permissions not roles, per-tenant scoping, role explosion → ABAC/ReBAC (Zanzibar — the right shape for content systems), **the real-world #1 authz bug is object-level (IDOR/BOLA)** not role design; Managed Identity kills the bootstrap secret (metadata endpoint = **SSRF target** — the Capital One lesson; credential-chain abstraction for local dev); secrets ladder ends at "no secret at all", committed secret = rotated not deleted, **dual-secret validity is what makes rotation zero-downtime**, cached-forever secret = rotation that never propagates. AEM: IMS S2S is the worked example.
- [ai-architecture.md](system-design/ai-architecture.md) — **LLM gateway** = API gateway with LLM twists: token-denominated rate limits (TPM not RPS), streaming latency metrics (TTFT, stall detection vs duration timeouts), retries cost money and are new samples, pre-decided degradation ladder; **RAG**: chunking is the highest-leverage decision, hybrid (vector+BM25+rerank) beats pure vector, **ACL filtering at query time or RAG is a data-leak machine**, embeddings are a derived copy (CDC; model upgrade = full reindex → dual-index blue/green), eval retrieval before blaming generation; **vector DB**: HNSW recall is a tunable, distance metric must match the model, **post-filtering can return 0 of top-k**, pgvector/OpenSearch before a dedicated store, it's an index not a system of record; **agents**: the model is an untrusted caller — validate args, user-identity authz (confused deputy), **prompt injection steers tool calls → security boundary at tool execution**; cap iterations/cost, idempotent tools (stochastic client), MCP as the boundary protocol; **models**: pin versions, eval suite + canary per bump, route by task tier, cost levers in leverage order (context discipline → caching → downshift → batch). AEM: Oak has no vector similarity → embeddings live externally.
- [url-shortener.md](system-design/url-shortener.md) — The classic design problem, focused on where it breaks rather than the hashing. Read-dominated (~100:1), redirect availability ≫ creation availability, base62 7 chars ≈ 3.5 T codes; code generation: **sequential counter = enumerable** (scrape every link) → scrambled counter / block allocation / random code, and **the DB unique constraint arbitrates, never check-then-insert**; hash-of-URL truncates into collisions and merges different users' links; **301 = cached forever by browsers → no analytics and no kill switch**, 302 + explicit `Cache-Control` (kill-switch latency = slowest cache layer), negative-cache 404s against enumeration; viral link = hot key (L1 + CDN); clicks emitted async, **bots and email scanners pre-click** (redirects must be safe GETs); abuse is the main operational cost: phishing laundering → reputation checks at creation *and later*, allowlist `http(s)` (no `javascript:`), isolate the short domain from your cookies and reputation. AEM: vanity paths/`RewriteMap`/CDN redirects/Edge Functions KV cover most asks; a real shortener lives outside AEM (no per-click writes on the JCR).
